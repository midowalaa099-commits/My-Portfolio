MVP Bank

A simulated bank built around exact amounts and safe retries.

This simulated application holds no real deposits. Amounts use integer minor units. Successful receipts are stored with customer-scoped request keys and checked on replay.

Decisions and tradeoffs

Store exact amounts

Store amounts as whole piastres, so EGP 1 is stored as 100.

Input rules are stricter. Money avoids decimal rounding errors.

Make retries safe

Keep the first receipt with its request key. A retry gets the same result.

The browser must keep the key. A retry cannot debit the account again.

Lock accounts in a fixed order

Make overlapping money changes wait their turn. Save balances with history.

Some requests wait. The rules are easier to test and follow.
