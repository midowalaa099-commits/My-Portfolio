FOOD-ORDERING API

Order App

A food-ordering API with customer, restaurant owner, and admin roles.

Customers order and track their own orders. Restaurant owners manage their restaurants, meals, and incoming orders. Admins review owner applications and oversee the platform.

View source ↗
  • Orders move through Pending, Preparing, On the way, and Delivered.
  • An order can be Cancelled only while pending.

My role

I built the API, access rules, owner applications, order flow, and scoped delivery tracking.

LaravelREST APIRole permissions

What I built

  • Separated 3 roles: customer, restaurant owner, and admin.
  • Checked ownership for addresses, meals, restaurants, orders, and tracking.
  • Kept 5 order statuses and controlled the allowed changes.
  • Added owner applications and limited who can update delivery locations.

Role boundaries

Customer
Place and view own orders. Cancel while pending.
Restaurant owner
Manage owned restaurants and meals. Update their orders.
Admin
Review owner applications and oversee the app.

Recorded results

  • 3 roles with explicit ownership rules.
  • 5 order statuses with controlled changes.
  • Delivery updates require the right owner, state, and permission.

Decisions and tradeoffs

Check the person and the record

Check the role and ownership for each action.

Each action needs a clear rule. One owner cannot change another owner’s records.

Keep the order flow on the server

Allow only valid changes. Customers can cancel while an order is pending.

The flow is strict. A client cannot skip steps or rewrite a completed order.

Limit delivery updates

Check the restaurant owner, the order state, and the delivery:update permission.

Tracking needs more checks. General sign-in access cannot write locations.

Limits and notes

A project demonstration. No order-volume or delivery-time claims.
